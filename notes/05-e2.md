## E2-freetext: how to phrase free-text answers ($0.029)
Variants (prompt rule for fields typed freetext by stage 0), 4 single-entry docs, everything else cached:
- **describe** (current): the field's description decides the phrasing.
- **verbatim**: copy the shortest passage that states the term, word for word.
- **concise**: answer in the length and format of the description's example, in the document's words, keeping every fact.

Scored strictly (`tools/validate.py`) and with a judge from another model family (claude-haiku-5.5; 47 distinct pairs,
2 calls, $0.0016). Spot check: the judge is too lenient on short identifier fields (accepted "Second Floor, West
Section, Suite 214W" for "Suite 214W"), so the realistic judged score applies the judge only to fields typed freetext,
matching the brief ("slightly more lenient on free-text fields").

| Variant | Strict | Judged (freetext only) | Judged (all text) | $ |
|---|---|---|---|---|
| describe | 0.845 | 0.889 | 0.902 | 0 (cached) |
| verbatim | 0.835 | **0.928** | 0.950 | 0.0137 |
| concise | **0.858** | 0.914 | 0.935 | 0.0137 |

Differences are near the ±0.03 noise on 4 documents. **concise** is best under strict scoring and within 0.014 of the
best judged score; **verbatim** is best judged but worst strict. Decision pending (user).

**Revision (user):** keep both verbatim and concise available (`FREETEXT_MODE`); note the judge's leniency on
identifier fields. Default set to **concise**.

## Pointer mode (user's template idea applied to single-entry documents) — $0.058

**Design.** Field handling decided from type + description only: *pointer* (numbers, dates, percentages, names, codes:
value + exact quote; code locates the quote, verifies or parses the value, sets citation + page from the found span),
*quote* (free text whose description says "as the lease states it"/"as written"/"verbatim": the exact document span is
the answer), *summary* (other free text, concise rule), *value* (booleans, lists, computed). Spreadsheet single-entry
lists: the pointer is a cell address and code reads the exact cell. Unfound quotes never invent or delete a value
(model value kept, lower confidence). `EXTRACT_STYLE=pointer`; default stays `value`.

| Approach | Strict | Judged (freetext) | Pages present / correct (lease_001, lease_003, om_001) | $ / doc |
|---|---|---|---|---|
| value (current) | 0.879 | 0.935 | 24/22, 36/36, 24/20 | ~0.0035 |
| pointer | 0.879 | 0.935 | **31/28**, 36/31, 24/**22** | ~0.0039 |

Accuracy is identical; pointer adds verifiable quotes and more correct pages on the scanned lease and the OM, but
picked a different (non-answer) occurrence on lease_003 five times. Quote-style answers come out as whole sentences
("Tenant shall use and occupy the Premises for general office purposes…") where the answers are fragments
("general office purposes"): strict misses, judged hits.

**Found on the way (E5 re-run under pointer mode):**
- My table-plan prompt changes had invalidated the cached E5 plans; the rent-roll-as-CSV plan failed its checks twice
  and the **LLM-writes-rows fallback ran 31 chunk calls** until the $0.04 run cap stopped it. Fixed: **two repair
  rounds**, and the fallback runs only for tables ≤ 400 non-empty rows; larger tables use the best plan and the job is
  marked PARTIAL ($0.0016 for the whole E5 re-run afterwards).
- The CSV rent-roll plan still misreads the total after repairs (0.946, flagged by its own check); the T12 terse plan
  varied (0.726 → 0.542: header rows included) — plan variance on information-starved field lists.

## Scanned and DOCX table documents — $0.020

Table field lists on inputs that had no grid (they returned nulls): routing in pipeline v1.
- **DOCX:** Word tables → grid rows (merged cells padded), paragraphs → one-cell rows; same plan path. Unit-tested on a
  generated DOCX (no sample).
- **Scanned / mostly scanned PDF** (≥ half the pages without a text layer): pages transcribed by the vision model with
  tables as Markdown → grid (one row per Markdown row, other lines as one-cell rows, rows keep their page, repeated
  page headers dropped) → same plan path.

Measured on a **scanned copy of budget_001** (every page rendered to an image, no text layer; answers known):

| Step | Score | Rows | Invented values |
|---|---|---|---|
| lease transcription prompt | 0.701 | 46/55 | 6 |
| table-specific prompt: one printed column = one Markdown column, never merge/split, wrapped text stays in its cell | 0.930 | 55/55 | 8 |
| + page 1 transcribed first, its column header imposed on the other pages (parallel); Markdown emphasis stripped; no spelling fixes | **0.991** | 55/55 | **0** |

Cause found: pages were transcribed independently and the model chose different layouts per page (code and name
merged into one cell on page 1, split on pages 2–3), so one plan's fixed columns misread whole pages. Digital
budget: 0.999. Cost ≈ $0.0067 per 8-page scanned table (vision ≈ $0.0006/page + plan). Sample outputs unchanged (0.939).

## Idea 1: load test at 10 jobs in flight (Docker, real pipeline, cache off) — $0.159

`app/eval/loadtest.py`: keeps 10 jobs in flight, tops up as jobs finish, polls every 2 s; 16 jobs = the 8 samples × 2
tenants (separate jobs; isolation checked). Container LLM cache off (realistic cost).

| | Baseline (WORKER_CONCURRENCY 4, LLM_MAX_CONCURRENCY 8) | Tuned (10, 24) |
|---|---|---|
| Terminal states | 16/16 SUCCESS, all valid | 16/16 SUCCESS, all valid |
| Lost / duplicated jobs; isolation | 0 / 0; ✓ | 0 / 0; ✓ |
| POST max | 145 ms | 447 ms |
| p50 / p95 / max per job | 129 / 203 / 227 s | **49.5 / 82.6 / 98.7 s** |
| Wall time, 16 jobs | 249 s | 99 s |
| Network errors (retried) | 7 | 1 |
| Cost | $0.105 ($0.0066 / doc) | $0.054 (see note) |

Baseline latency was mostly **queueing**: table documents needing ~20 s of work waited ~200 s behind scanned leases in
4 slots. **Defaults changed to 10 jobs per worker and 24 concurrent model calls.** The tuned run's lower cost is an
artefact (both copies of each document in flight at once share identical requests through the client's in-flight
deduplication); distinct documents still cost ~$0.0066 each. With the cache off, fresh plans/extractions vary run to
run (one T12 copy 0.909, OM copies 0.897 / 1.000; mean 0.934 vs 0.942). Remaining latency is processing time,
dominated by scanned leases (67–99 s) → ideas 2 and 3.

## Ideas 2 and 3: selective vision, lower vision resolution — $0.013

**Per-page study ($0)** on both scanned leases (+ the scanned budget): labels from the cached vision transcriptions
(did OCR lose an answer value that vision caught? handwriting? table?) against Tesseract-only signals. Vision marks
"handwriting" on nearly every page of the 1993 lease (initials), so the useful label is *OCR lost an answer value*:
lease_001 p2 (handwritten deposit), p25 (garbled guarantor), lease_003 p3 (rent table). Rule = any of: mean OCR
confidence < 0.88; ≥ 5% words below confidence 50; ≥ 15% lines with 3+ numbers; ≥ 10% "LABEL:" lines. It flags all 3
needed pages and 5/25 + 2/21 pages overall. Table documents keep full vision (consistent layout across pages).

| | Strict | Judged | Scanned-lease cost |
|---|---|---|---|
| Full vision | 0.879 | 0.935 | ~$0.022 |
| **Selective (adopted, `SCANNED_MODE=selective`)** | 0.873 | 0.923 | **~$0.009** |

Changed cells: one yes/no judgement (early termination, a known shared interpretation error) and two free-text
phrasings; no OCR-sensitive value changed.

**Resolution (idea 3), on the 4 hard E1a images:** 1,100 px cuts vision input ~45% (cost −25%) but lost the landlord's
legal name on the hardest page; with selective vision the saving would be ~$0.001 per scanned document → **kept 1,500 px**
(`VISION_LONG_SIDE` available).

**Result:** sample mean 0.936 (was 0.939); uncached cost over the 8 samples $0.0334 → **$0.0042/doc (was $0.0075, −44%)**.

## Idea 6: stage 0 fills in terse field lists — $0.027

Unseen field lists may come with little or no description. A field is *terse* if its description is empty, repeats its
name, or has ≤ 3 words; when ≥ 25% of a field list is terse, one extra call writes standard real-estate definitions for
those fields (inferring the document type from all field names together), then the normal analysis runs on the
expanded list. Rich field lists are untouched (none of the 6 sample lists triggers it; the OM's single "City." does not).

| Terse + renamed variant (E5) | Before | Expansion v1 | **Expansion v2 (adopted)** | Full descriptions |
|---|---|---|---|---|
| lease_002 | 0.650 (0 invented) | 0.550 (9 invented) | **0.800 (0)** | 0.825 |
| lease_001 | 0.625 (0) | 0.610 (6) | **0.750 (0)** | 0.850 |
| T12 | 0.542 (140/119 rows) | 0.542 | **0.781 (119/119)** | 0.999 |

v1 regressed because the expansion invented absence conventions ("0 if absent", "empty string if absent"), which the
pipeline applied as defaults where the answers are null. v2: "null if the document does not state it", with only two
exceptions (yes/no → false; lists → empty list). Sample outputs unchanged (replay 0.936).
